## 1. 模块设计概述

### 1.1 业务背景及目标

维护者（用户角色）在浏览器里看到贴顶的紫色文字链、点开图就是裸 PNG、深色下输入框看不清，也没有办法自己换成另一种明暗（业务问题）。顶栏改为按钮，登录改为卡片，三个图地址在要网页时返回承载页，深色控件可辨，明暗选择四页一致（业务价值）。

### 1.2 边界说明

| 边界 | 说明 |
|------|------|
| 做 | 管理端、阅读页、首页、三个图地址的 HTML 外观；明暗 Cookie；图地址的网页/PNG 分流 |
| 不做 | 不新增路径；不改 PNG 字节和 ETag；不改机器 JSON 与 env；不改 `/admin/api/*`；不改 Kindle 画面；不把语言改成两段开关 |

### 1.3 设计决策

| # | 决策点 | 选择 | 理由 |
|---|--------|------|------|
| AD-0 | 混合模式 | 不适用。无领域对象写入 | 工具类 |
| AD-1 | 是否新接口 | 不新增。三个图地址和管理端、阅读页、首页都已存在 | 分流只改变「要网页」时的正文类型 |
| AD-2 | 分流信号 | 与阅读页同一套：`format` 优先，其次 Accept 里写明的 `text/html` | 不看 User-Agent。wget 的 `*/*` 继续拿 PNG |
| AD-3 | 强制原图 | `format=png` | 与 `format=json` 要回机器原文对齐。不用 `format=raw` |
| AD-4 | 明暗取值 | 只持久化 light / dark。缺省跟随系统 | 用户要的是在两种外观之间切换，同时保留自动探测作为还没选时的行为 |
| AD-5 | 明暗记住 | Cookie `kc_theme`，路径 `/`，一年，四类网页共用 | 换页不丢 |
| AD-6 | 语言控件 | 保持一个按钮 | 双语模块已确认，截图里也是单独的 English |
| AD-7 | 灰度图 | 不反相 | 深色页面里仍要看到设备上的那张灰图 |
| AD-8 | 缓存 | HTML 与 PNG 成功响应都带 `Vary: Accept`。HTML 不带图片 ETag | 避免缓存把承载页发给 Kindle |
| AD-9 | 心跳 | 图片承载页不调用心跳 | 心跳仍只在拉取 env 时记录 |
| AD-10 | 登录文案 | 不改现有句子 | 本次改的是版式，不是用词 |

### 1.4 领域对象总览

| 对象 | 角色 | 说明 |
|------|------|------|
| 明暗选择 | 过程数据 | Cookie。枚举 `ui_theme` |
| 图片承载页 | 过程数据 | 三个现有地址上的 HTML |
| PNG 资产 | 关联对象 | 不改字节 |
| 台历配置 | 关联对象 | 不新增字段 |

子流程：无。

### 1.5 上下文映射

| 对方 | 关系 | 说明 |
|------|------|------|
| 页面渲染 | 上游 | 承载页展示已经画好的 PNG |
| 接口阅读页 | 同站页面 | 顶栏样式对齐。阅读页分流规则不改 |
| 网页语言 | 同站 | 仍用 `ui_lang` 与语言 Cookie |

## 3. 应用层约定

### 3.1 接口规范

无新路径。

| 项 | 约定 |
|----|------|
| 基础路径 | 仍是 `/`、`/admin`、四个阅读地址、三个图地址 |
| HTTP 方法 | 沿用 GET。明暗不提交 POST |
| 响应 | 要网页时 `text/html`；图地址的其余情况 `image/png`。不引入统一包装体 |
| 权限 | 这些页面本来就是公开的。管理端未登录也能看到顶栏和登录卡 |
| 用户类型 | 维护者可操作。家庭用户无此菜单 |

### 3.2 依赖与约束

| 方向 | 对象 | 约束 |
|------|------|------|
| 依赖 | 三个图地址的现有 PNG | 只在不要网页时原样返回 |
| 依赖 | `prefer_html` 的判定 | 图地址复用，并在其前增加 `format=png` 强制 PNG |
| 依赖 | `ui_lang`、语言 Cookie | 不改规则 |
| 被依赖 | 管理端预览、首页预览的图片标签 | 必须仍收到 PNG |
| 被依赖 | `dash.sh` 的 wget/curl | 必须仍收到 PNG |

不得用 User-Agent 分流。

### 3.3 权限模型

| 角色 | 说明 |
|------|------|
| 维护者 | 看页面、切换明暗和语言、返回首页、查看原图 |
| 未登录访客 | 打开 `/admin` 时同样看到顶栏和登录卡 |
| 家庭用户 | 无此操作 |
| 机器客户端 | 只收到 PNG 或原来的 JSON/env |

| 操作 | 未登录 | 已登录 | 机器 |
|------|--------|--------|------|
| 看见顶栏 | 可以 | 可以 | 不看 HTML |
| 切换明暗 | 可以 | 可以 | 不发生 |
| 打开 PNG | 可以 | 可以 | 可以 |
| 保存配置 | 不因本模块发生 | 仍走原接口 | 不发生 |

数据权限：无新业务数据。

## 4. 契约

### 4.1 领域模型

无表、无聚合根、无状态机、无领域事件。

不变量：

| # | 不变量 |
|---|--------|
| INV-1 | 不声明网页时，三个图地址的 PNG 正文和 ETag 与现在相同 |
| INV-2 | `format=png` 覆盖「要网页」 |
| INV-3 | 直接返回给设备的 PNG 不读取 `kc_theme`，也不读取语言 Cookie |
| INV-4 | `kc_theme` 只有 light / dark 会改变外观；其它值跟随系统 |
| INV-5 | 四类网页读取同一枚 `kc_theme` |
| INV-6 | 成功的 HTML 与 PNG 响应包含 `Vary: Accept` |
| INV-7 | 切换明暗不写台历配置、不改会话 |

### 4.2 状态模型

明暗不是单据状态。

| 情况 | 外观 |
|------|------|
| 无 Cookie，或值不是 light/dark | 跟随系统 |
| Cookie = light | 浅色，即使系统是深色 |
| Cookie = dark | 深色，即使系统是浅色 |

没有从「已选」回到「跟随系统」的接口。清掉 Cookie 才会重新跟随。

### 4.3 子流程

无。

### 4.4 接口设计

#### 接口清单

| 编号 | 名称 | 方法 | 路径 | 变化 |
|------|------|------|------|------|
| C-1 | 打开首页 | GET | `/` | HTML 顶栏增加明暗按钮。`format=json` 的机器清单不变 |
| C-2 | 打开管理端 | GET | `/admin` | HTML 顶栏与登录卡。`/admin/api/*` 不变 |
| C-3 | 打开阅读页 | GET | 四个已有数据地址 | 仅要网页时的顶栏位置和按钮样式 |
| C-4 | 打开分区图 | GET | `/r/<page>/<region>.png` | 要网页时改为承载页；否则 PNG 不变 |
| C-5 | 打开时钟字形 | GET | `/r/today/clock/<glyph>.png` | 同上 |
| C-6 | 打开整页图 | GET | `/dashboard.png` | 同上。`page`、`offset` 仍决定是哪一张 |

无动作接口、无服务接口、无工作流回调。

#### 4.4.1 图地址分流

按顺序，命中即停止：

| 顺序 | 条件 | 结果 |
|------|------|------|
| 1 | `format=png` | PNG |
| 2 | `format=html` | 承载页 |
| 3 | `format` 为其它非空值 | PNG |
| 4 | Accept 里 `text/html` 的质量 > `application/json` 的质量，且 `text/html` 质量 > 0 | 承载页 |
| 5 | 其它：没有 Accept、只有 `*/*`、质量相等、只有图片类型 | PNG |

浏览器地址栏会带上 `text/html`，走第 4 步。图片标签通常不带 `text/html`，走第 5 步。Kindle 的 wget/curl 是 `*/*`，走第 5 步。

承载页里的 `<img>` 必须带 `format=png`，并在网页语言为英文时带 `lang=en`。这样嵌进去的图不会再被协商成 HTML，图上的文字与页面语言一致。设备自己来拉、地址里没有网页语言时，仍按设备语言出图。

#### 4.4.2 PNG 响应

状态码、`image/png`、ETag、`Cache-Control` 与现在相同。额外加上 `Vary: Accept`。304 的条件不变。

未知 page、region、glyph：状态码 404。不要网页时正文仍是 `not found`。要网页时可以是带返回首页的短 HTML，状态码仍是 404。

#### 4.4.3 承载页

`text/html`。顶栏含返回首页、语言、明暗。正文是一张图，下面有查看原图，地址为同一路径加 `format=png`（以及已有的 `page`、`offset`、英文时的 `lang=en`）。不增加翻页或翻月控件。

#### 4.4.4 明暗

服务端若读到 `kc_theme=light` 或 `dark`，在页面根元素写上对应标记，第一屏就用该外观。点击按钮只改这个标记和 Cookie，不发请求。

当前外观是浅色时，按钮提示「切换到深色」，图标表示将要进入深色。当前是深色时相反。

#### 4.4.5 深色控件

只约束管理端设置页在深色（系统深色且未选浅色，或已选深色）下的外观：

| 控件 | 要求 |
|------|------|
| 文本、口令、搜索、数字 | 背景 `#2a2622`，文字 `#f4f1ea`，边框 `#8a8175` |
| 数字框上下箭头 | 箭头 `#f4f1ea`，箭头所在底 `#2a2622`。不能是白底上的灰箭头 |
| 复选框 | 边长至少 16px。未勾选边框 `#8a8175`。勾选标记用 `#f4f1ea` 或 `#7eb6ff`，在深底上可辨 |
| 排序上下按钮 | 与普通按钮同一套深底浅色箭头 |
| 禁用行 | 背景仍是 `#2a2622`，文字 `#c8bfb4`，不透明度不低于 0.75。禁止在白底上做透明 |

浅色外观保持现在的纸感，不改布局栅格。
