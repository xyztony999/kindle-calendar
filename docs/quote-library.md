# 个人语录库格式

> **状态更新（2026-11-24）**：个人语录库上传已实现（模块 admin-content-pack）。管理端一言分区选「个人库」后上传本格式 JSON，整份替换、逐条校验报错；文件存 `data/quotes_personal.json`，纳入全量备份/恢复。一言来源现为四态：本地语料库 / 在线 / 自定义 / 个人库。
>
> **状态更新（2026-10-27）**：一言已内置官方开放句子库（`server/quotes_library.json`，AGPL-3.0，来源 hitokoto.cn），管理端可选 12 个分类（模块 quote-library）。

本格式用于个人语录库上传（`POST /admin/api/quotes-personal`，multipart 字段 `file`）。上传整份校验（下列全部约束），失败一次性返回错误条目索引与字段，不静默截断、不部分导入；通过后原子写入并热替换，不自动切换来源模式——需在管理端选「个人库」并保存后生效。个人库与官方库互不覆盖，中英页共用，按日确定性轮换；空库或未上传时回退内置离线诗词。管理端“自定义文案”仍通过逐条输入使用；设置导入接收的是完整台历设置，不能直接导入本文件。在线自定义接口地址功能仍未实现（需单独设计，见下文边界）。

## JSON 格式

文件使用 UTF-8 编码。顶层 `schema_version` 固定为整数 `1`，`quotes` 为非空数组，每项含 `text` 和 `from` 字符串。示例见 [quote-library.example.json](quote-library.example.json)。

```json
{
  "schema_version": 1,
  "quotes": [
    {"text": "此心安处是吾乡。", "from": "苏轼《定风波》"},
    {"text": "今天也留一点时间读书。", "from": ""}
  ]
}
```

字段约束沿用当前自定义文案：

- `quotes` 包含 1–100 条。
- `text` 去除首尾空白后为 1–32 个 Unicode 字符。
- `from` 为出处、作者或二者合并，去除首尾空白后最多 16 个 Unicode 字符；没有出处使用空字符串。
- 两个字符串都不能包含回车或换行，不接受 HTML。字符数不按 UTF-8 字节数计。
- 导入前应完整校验整份文件，指出错误条目的索引，避免静默截断或只导入部分内容。

语录库的 `schema_version` 与完整台历设置的版本号独立，不能混用。

## 接入边界

本地 JSON 库和在线服务都应经过来源适配器转换，向现有显示层提供同一个结果：`{"text": "…", "from": "…"}`。第三方的 `content`、`author`、`source` 等字段由适配器映射，不进入显示层；`from` 的合并规则须明确，不能自动丢失作者或出处。个人库上传已按此落地（`server/quotes.py` 的 `validate_personal` / `personal_quote`）。

在线接入仍需单独设计地址限制、认证信息保管、超时、缓存和重定向处理，不能把语录库格式视为允许任意地址请求。成功返回的内容必须通过上述校验；拉取失败或内容无效时回退现有离线诗词，避免台历空白。轮换、去重、语言选择及更新频率由来源实现决定，不作为这版文件格式的隐含约定。

`server/quotes.py` 的 `get_quote()` 输出 `text` / `from`；个人库校验复用 `server/settings.py` 的 `TEXT_MAX` / `FROM_MAX` / `CUSTOM_MAX` 常量（32 / 16 字与 100 条），与自定义文案同一口径。
